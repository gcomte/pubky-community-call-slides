Gabriel, approximately two minutes. This is a cumulative update from v0.6.0 to the latest release, v0.14.0. Small version labels identify when each feature arrived; these are not all new in v0.14.0.

  • Live updates: v0.7.0 added SDK subscriptions to server-sent events (SSE) in Rust and JavaScript/WASM. Apps can react to homeserver changes. The server event-stream endpoint already existed in v0.6.0. v0.7.0 release.
  • App-specific authentication: v0.10.0 introduced grant-based credentials with scoped access, revocation, and automatic refresh. This describes SDK capabilities, not a claim that every app has migrated. v0.10.0 release.
  • Private storage: /priv arrived in v0.10.0 as experimental, alpha functionality; the release explicitly advises against production use. Access is controlled by the homeserver. It is not end-to-end encryption: server administrators can read and write this data. APIs may change. Private-storage access model.
  • Native HTTPS fallback: v0.8.0 lets native clients use an advertised HTTPS domain when the direct PubkyTLS endpoint cannot be reached. Browser/WASM clients already used domain endpoints. v0.8.0 release.
  • Error-response limits: v0.13.0 bounds SDK error-body reads to 4,096 bytes by default. This limit applies to error responses, not normal successful downloads. v0.13.0 release; PR #608.
  • Safer writes are a homeserver change in v0.14.0: uploads are staged before finalization, and commit finalization is protected against a client disconnect. v0.14.0 release; PR #637.

Structured errors, browser-session persistence, and Postgres support were already part of v0.6.0; do not present them as new in this interval. Upgrading crosses breaking changes: use the v0.10 migration guide and review the intervening release notes.

Nexus Scout

nexus-scout.pubky.app/llms.txt

Nexus Scout is a public, read-only query gateway to the Nexus social graph. An LLM assistant can read the schema, translate a social graph prompt into Cypher, and call Scout. Scout validates the query, runs it against Neo4j, and returns JSON; Scout itself is not the LLM. No account, API key, or installation is required for the public endpoint.

Start with the LLM guide and graph schema. Both examples below were executed against POST https://nexus-scout.pubky.app/v1/query. These are fixed snapshots of this instance's indexed graph, not a live feed or a claim to cover all Pubky activity.

Replies beyond current follow lists: captured 7 October 2026 at 10:39:11 UTC. Of distinct reply-to-parent links between different indexed authors, 29.3% (rounded) go from a replying account to an author it does not currently follow. Scope: current indexed follow graph; self-replies excluded. This is not the follow relationship at the time of posting. It tests only whether the replier follows the parent post's author, not the reverse direction.

MATCH (replier:User)-[:AUTHORED]->(reply:Post)
      -[:REPLIED]->(parent:Post)<-[:AUTHORED]-(author:User)
WHERE replier.id <> author.id
WITH DISTINCT replier, reply, parent, author
RETURN count(*) AS cross_account_reply_links,
       sum(CASE WHEN exists((replier)-[:FOLLOWS]->(author))
                THEN 0 ELSE 1 END)
       AS replies_to_accounts_not_followed
LIMIT 1

Parameters: none. Request limit: 1. This returns one aggregate row; it does not cap the reply links counted.

Mutual follows: captured 7 October 2026 at 10:50:29 UTC. Of distinct directed follows between different accounts in the indexed graph, 44.9% (rounded) have a reverse follow. Self-follows are excluded and parallel relationships are deduplicated. Each reciprocal pair contributes two directed follows. This is a percentage of follows, not of accounts or pairs. Exact aggregate responses and calculations are retained in the ignored working artifacts.

MATCH (a:User)-[:FOLLOWS]->(b:User)
WHERE a.id <> b.id
WITH DISTINCT a, b
RETURN count(*) AS directed_follows,
       sum(CASE WHEN exists((b)-[:FOLLOWS]->(a))
                THEN 1 ELSE 0 END) AS mutual_directed_follows
LIMIT 1

Parameters: none. Request limit: 1. This is one aggregate result row; the limit does not limit the relationships counted. Calculate mutual_directed_follows / directed_follows × 100 and round to one decimal place.
